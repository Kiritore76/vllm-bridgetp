# GoodOutput v5：慢间隔比例和单次停顿门禁

2026-10-03 更新。v4 仅用请求平均 TPOT，保留为历史对照；STAY/MIGRATE 配对从本版起以 v5 为主指标。每个已完成请求须同时满足：

1. 平均可见相邻输出 token 间隔 ≤ 50 ms；
2. 超过合同 TPOT 50 ms 的间隔数 / 可见间隔总数 ≤ 1%；
3. 任一可见间隔 ≤ 合同 handoff 上限 1000 ms；
4. 请求 E2E ≤ 60 s；迁移锚请求的 handoff ≤ 1000 ms。

单 token 输出没有相邻间隔，按间隔条件通过。未完成或数据缺失的请求不能算成功。TTFT 不设独立合格门槛，但请求等待仍计入整池运行时长。整池 `goodoutput_v5_tokens_s` 是合格请求的输出 token 总数除以从首个请求发出至最后请求结束的共同运行时长。每个请求的 `bad_interval_rate`、`max_itl_ms` 及失败原因可从审计行复核。1% 是当前明确的工作阈值，未来业务 SLO 如有不同应在配对前修订，不得看完结果后调整。

1000 ms 是合同硬上限，不是本轮约 348 ms 的实测 handoff。一个 1001 ms 可见间隔即使平均 TPOT 很低，也判失败。handoff 时间还单独受同一合同上限约束；同一停顿不重复扣 token。

## 证据和原因判断

`control/results/target-solo-burst-20261003T132033Z-1267.tar.gz` 是独立 TP4、没有迁移的同机探针。四个 2048-token prompt 在 60 ms 内到达。首个请求首次输出约 1.03 s，随后在约 2.04、3.06、4.07 s 的间隔各停顿约 1.01 s；第二个请求首次输出约 3.06 s，随后到约 4.07 s 也停顿约 1.01 s。后续请求的首次输出分别与这些停顿结束时间重合。单请求对照的 TTFT 约 1.03 s，未出现 >50 ms 的 decode 间隔。

时间重合强烈指向新到达的长 prompt prefill 与已有请求的 decode 竞争 TP4 计算/调度预算；没有迁移，因此这些 1 s 停顿不是 handoff 或 M5 特征读取造成的。现有数据没有逐调度步 GPU trace，尚不能确认具体 kernel、队列顺序或单个参数的责任。服务器启用了 chunked prefill；启用本身没有保证这组负载无长间隔。应在同机、同 HEAD、同到达流下对比不同 prefill 调度预算，并同时衡量 TTFT、吞吐与最大间隔，再决定是否调整服务端参数。
