# Phase 9 D3 当前结果、公平比较与 052 边界缺陷

## 1. 当前证据状态

截至本次分析，BF16 与 FP16 正式 D3 各有 49 个可配对请求；编号 052 在两种精度下均因同一个恢复阶段机械错误缺失。因此，49 对结果可用于描述迁移后的数值一致性，但不能把修复后单独补跑的 052 与旧 49 条直接混成同一提交版本下的正式 50 条主队列。

已有 smoke 给出的旧口径结果为：

- BF16：A=[256,256]，B=[136,71]，C=[63,71]，D=[63,0]；D-B=[-73,-71]。
- FP16：A、B、C、D 均为 [256,256]；D-B=[0,0]。

这支持“BF16 下跨拓扑和迁移均可能较早产生 token 分歧，而 FP16 smoke 中该分歧消失”的精度敏感性观察；但正式结论仍应基于完整、同版本的配对队列。

## 2. 旧比较方法及其问题

旧方法使用 A/B/C/D 四组：

- A：TP1 原生重放对 TP1 原生重放，检查实验基线可重复性。
- B：TP1 原生输出对 TP4 原生输出，量化纯拓扑差异。
- C：调度或批处理控制组。
- D：TP1 迁移到 TP4 后的输出与 TP1 原生完整输出比较。

旧的 `D-B` 直接比较“迁移后、从切换点继续 decode 的后缀”和“TP4 从 prompt 开始原生生成的完整轨迹”。两者进入 TP4 decode 的历史、缓存构造和随机数消费路径并不一致，因此 B 不是 D 的严格反事实基线。它容易把拓扑、调度、前缀历史和迁移本身混在一起。

## 3. 当前采用的公平比较

公平口径把比较锚定在同一个 cutover 前缀和同一个续写位置：

- R：源侧实际生成并被迁移快照承诺的前缀，作为所有后续比较的共同条件。
- B′：不执行 KV 搬运，但让目标 TP4 在相同 R 和相同 decode 起点下恢复/重算后续 token，表示同条件下的跨拓扑基线。
- D：执行真实 KV 迁移，在相同 R 和相同 decode 起点下续写。
- 主估计量：`D - B′`，即真实迁移相对公平跨拓扑反事实所增加的首个分歧位置损失。

这比旧 `D-B` 更公平，因为它控制了：

1. 相同 prompt；
2. 相同 cutover token 数；
3. 相同已承诺前缀 R；
4. 相同目标拓扑；
5. 相同续写起点与比较区间。

因此，新口径更接近要回答的问题：在系统本来就存在跨拓扑数值不确定性的前提下，KV 迁移是否引入了额外、可观测的数值偏差。

旧口径仍可作为描述性结果保留，但不应作为迁移非劣效性的主检验。

## 4. 052 失败原因

052 不是 C 系列数据不足，也不是 BF16 数值分歧导致的失败，而是确定性的 block 边界错误：

- prompt token 数：33；
- cutover 输出 token 数：160；
- 调度器当前已知 token 数：193；
- 已完成计算并进入迁移快照的 token 数：192；
- block size：16；
- 快照需要 `ceil(192/16)=12` 个 block；
- 调度器已为第 193 个、尚未计算的 token 预分配第 13 个 block。

旧 connector 要求“调度器已分配 block 数必须与快照 block 数完全相等”，于是把合法的单个 pending tail block 误判为快照布局不一致，抛出：

`ValueError: Target block allocation differs from live snapshot`

这解释了为什么 BF16 和 FP16 都稳定缺少同一个 052：它是输入长度、cutover 和 block size 共同触发的机械边界条件，与 dtype 无关。

## 5. 修复策略

修复遵循两个约束：

1. 允许调度器比快照恰好多分配一个尚未计算的尾 block；
2. 恢复元数据只包含快照覆盖的前 12 个 block，不能覆盖或伪造第 13 个 pending block。

同时继续拒绝以下异常：

- 已分配 block 少于快照所需；
- 比快照多两个或更多 block；
- token 数、block size 或 cache group 布局非法。

该校验被提取为共享的纯函数，并同时用于 streaming connector 与 file restore connector，避免在线和离线恢复路径出现不同判定。

## 6. 结果使用边界

修复后应先补跑 052，确认迁移和控制链路均完成；该结果属于 post-fix 验证。若论文需要正式、同质的 50-RID 推断，应在同一修复提交上重跑完整 50 条 BF16/FP16 队列。若只需要证明缺失原因和工程修复有效，可以将旧 49 对作为修复前描述性结果，将 052 作为单独的边界回归证据，明确二者代码版本不同。

最终迁移有效性不应只用“是否逐 token 完全相同”定义，而应报告：

- A 是否证明基线可复现；
- 精度变化是否使分歧收敛；
- 公平口径下 `D-B′` 的配对分布及置信区间；
- 迁移完成、KV 恢复与请求连续性的工程证据；
- 对旧 `D-B` 的描述性结果及其混杂限制。
