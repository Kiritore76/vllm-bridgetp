# GoodOutput 审计后的请求级 SLO 修订（v2）

日期：2026-10-03。此修订**保留** `GOODOUTPUT_METRIC_V1_AND_AUDIT_20261003_CN.md` 中的逐 token GoodOutput 公式和原始结果；不追改既有 runner 的 `anchor_slo.success` 历史判定。

## 为什么需要区分定义

旧 runner 对锚请求采用“全部可见 ITL 均 ≤50 ms”才算严格成功。一个 1024-token 请求有 1023 个间隔，只要其中一次波动就整条失败。四个已拿回的高压包在这种口径下请求级成功数均为 0/13；但超限间隔只占约 0.38%–0.65%。这个全有或全无判定随请求变长而更难通过，不适合作为唯一的服务质量指标。

同时，改成 p99 TPOT **不能**让本批高压实验多数成功。现有阈值仍为 TTFT 1000 ms、TPOT/ITL p99 50 ms、E2E 60000 ms、迁移请求 handoff 1000 ms。12 个背景请求在前两包中 p99 TPOT 均达标，但只有 2 个 TTFT 达标；晚启动包只有 3 个背景 TTFT 达标。该 workload 同时发出多条长输出压力请求，不能仅凭它代表正常负载。

## 后续并列报告的三个口径

1. **主目标 GoodOutput v1**：TTFT/E2E 达标的已完成请求中，逐 token 统计前一个可见 ITL ≤50 ms 的输出，单位 tokens/s。公式与版本保持不变。
2. **请求级 SLO v2**：已完成请求的 TTFT ≤1000 ms、E2E ≤60000 ms、该请求可见 ITL 的 p99 ≤50 ms；迁移请求还要求 handoff ≤1000 ms。单 token 请求没有 ITL 样本，不因 p99 未定义而失败。p99 使用与背景 runner 相同的线性插值。报告成功请求数/率以及达标请求输出 tokens/s。
3. **旧严格口径**：所有 ITL 都 ≤50 ms 的请求成功数，继续标为 `legacy_strict`，用于历史对照，不再称为唯一的 SLO 成功率。

此外必须并列报告超限间隔率、p95/p99 TPOT、最大可见 gap、handoff p95/p99、抢占/OOM 和按 TP1/TP4 分池结果。p99 允许少量尾部间隔超限，不能靠它遮蔽严重长停顿；迁移后严格核对 handoff 与最大 gap。不能在观察结果后把 50 ms 或 1000 ms 调大以制造“大部分请求成功”。

## 下一轮实验的使用方式

对同一到达流同时报告 GoodOutput v1、请求级 SLO v2、旧严格口径和原始违规率。先在 TP4 空闲、TP1 低/中负载下做 STAY/MIGRATE 配对，确认**STAY 基线**在预先设定的 SLO 下是否多数成功；再逐步提高负载。若 STAY 本身也大面积 TTFT 失败，应调整实验提供负载或容量规划，不能靠修改阈值“修复”模型。高压 W3 仍保留作容量与抢占边界实验，其 SLO 成功率不预设为多数。
